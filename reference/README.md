# reference (해설지) — v2: 프레임 단위 분석판

영상을 프레임 단위(장면전환 47곳)로 전부 뜯어서, 화면 흐름·문구·여백·버튼 색상(픽셀 샘플링)까지
최대한 1:1로 맞춘 버전입니다.

**바뀐 것 없이 그대로 가져온 것:** 화면 구성·순서, 버튼/라벨 문구, 레이아웃(카드 모양, 여백, 그리드),
색상(이체 버튼 `#4092EF`, ATM출금 `#6EB4FF`, 하단 탭 FAB `#297BEB` 등 실제 영상에서 픽셀 추출),
상세내역 바텀시트의 필드 구성, 금액을 "20만원"처럼 한글로 같이 보여주는 방식.

**의도적으로 바꾼 것:** 은행명(IBK→"마이뱅크"), 실제 계좌번호/잔액/실명 → 전부 가짜 데이터.
이유는 두 가지입니다 — ① 영상에 찍힌 실제 계좌번호·잔액·거래 상대방 이름은 남의 눈에 노출되면 안 되는
개인 금융정보라서, ② 레포가 나중에 공개되면 실제 은행을 그대로 베낀 로그인/송금 화면은 피싱 앱처럼
오인될 수 있어서. UI/UX 패턴을 베끼는 연습 자체는 문제가 없지만, 실명·실계좌·실브랜드 세 가지는 바꿨습니다.

## 실행 방법

```bash
cd reference/backend
npm install
npm start
```

`http://localhost:3000` 접속. 백엔드가 frontend 폴더를 같이 서빙해서 포트 하나로 끝남 (CORS 불필요).

## 화면 흐름 (영상과 동일한 순서)

```
대시보드 (톡톡송금 탭)
  └ [이체] 버튼
      → 받는사람 선택 ("누구에게 보낼까요?" + 최근 이체 목록)
          → 금액 입력 ("내 계좌에서" / "받는 분 계좌로" / 금액 / 다음)
              → 이체 확인 ("OOO님께 OOO원을 보낼까요?" / 보내기)
                  → 이체 완료 (체크 아이콘 / "OOO원을 보냈어요" / 공유·확인)
  └ [최근 이체내역] → 거래내역조회 (필터 + 리스트)
                          └ 항목 탭 → 상세거래내역 바텀시트 (거래일시/구분/내용/상대은행/계좌/예금주명/메모)
  └ [☰] → 전체메뉴 오버레이 (검색 + 카테고리 탭 + 최근 이용 메뉴)
```

## 구조

```
reference/
  backend/
    server.js      # Express API: 계좌/최근이체목록/거래내역/이체 실행
  frontend/
    index.html     # 화면 7개 + 바텀시트 + 메뉴 오버레이, 전부 하나의 페이지 안에서 토글
    styles.css     # 영상에서 픽셀 샘플링한 색상 반영, 모바일 우선 반응형
    app.js         # 화면 간 state 전달 (받는사람 → 금액 → 확인 → 완료) + fetch API 연동
```

## 핵심 개념 (막힐 때만 보기)

1. **여러 화면 사이에서 상태 들고 다니기** — `app.js`의 `state` 객체 (`selected`, `amount`).
   받는사람을 고르면 `selectRecipient()`가 `state`에 저장하고, 금액 화면은 그 `state`를 읽어서
   화면에 채운다. 서버에 보낼 때도 이 `state`를 그대로 body에 담아 POST한다 — 여러 단계짜리
   폼(멀티스텝)은 결국 "다음 화면으로 뭘 들고 넘어갈지"를 설계하는 문제다.

2. **GET으로 읽고 그리기** — `loadAccount()`, `loadRecipients()`, `loadTransactions()`.
   패턴은 항상 동일: `fetch` → `res.json()` → `.map().join('')`로 HTML 문자열 생성 →
   `innerHTML`에 통째로 넣기. 그 다음 `querySelectorAll`로 각 항목에 클릭 이벤트를 다시 건다
   (innerHTML로 새로 그리면 이전 이벤트 리스너는 사라지므로 매번 다시 걸어야 함).

3. **POST 성공/실패 나눠 처리하기** — `btn-send` 클릭 핸들러. `res.ok`가 false면(`400`)
   `alert`만 띄우고 화면은 유지, 성공이면 받은 데이터로 완료 화면을 채우고 넘어간다.

4. **디스플레이 토글로 화면 겹쳐 쓰기** — 바텀시트(`#detail-sheet`)와 메뉴(`#menu-overlay`)는
   `.screen`과 별개로 `.open` 클래스 하나로만 보이고 숨긴다. `position: fixed` + `z-index`로
   다른 콘텐츠 위에 뜨게 하는 게 핵심 — 모달/바텀시트의 공통 구현 방식.

5. **탭바를 화면별로 숨기기** — `styles.css`의 `#screen-dashboard.active ~ .tabbar`.
   CSS만으로 "대시보드일 때만 보이기"를 구현 (JS로 클래스 토글하는 대신 형제 선택자 활용).
